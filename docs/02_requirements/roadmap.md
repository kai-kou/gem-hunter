### 0.2. 🔴 前提: 期日は存在するが未確定である（`D-9` / `RK-6`）

したがって本書は **絶対日付でスケジュールを引かない**。あわせて **工数（人日・週数）の見積もりも書かない**（根拠のない数字になるため・`D-9` の従属事項）。

代わりに、期日がなくても **今すぐ確定できる 3 つ** で時間軸を表現する。

| # | 本書が確定させるもの | 理由 |
|---|---|---|
| 1 | **到達順序**（どのマイルストーンを、どの順で通るか） | 期日が決まっていなくても順序は決まる。順序が決まれば「次に何をするか」は一意になる |
| 2 | **各マイルストーンの通過判定**（機械的または実機で検証できる形） | 「終わったつもり」を防ぐ。判定できないマイルストーンは存在しないのと同じ |
| 3 | **期日が確定したときの記入手順**（§5） | 期日が来たときに何をどこへ書くかを先に決めておく |

🔵 **「未確定」は「無期限」ではない。** 日付だけが未定であり、順序・判定・削減順序は本書で確定している。

## 3. マイルストーン定義

### M-1: 歩く骨格が通る（スライス `S-0`）

- **ゴール**: 「検索 → 一覧 → 詳細 → 一覧」が端から端まで細く通り、**後から変えると全体を書き換える境界が固定される**
- **束ねるスプリント**: `SP-1` → `SP-2` → `SP-3` → `SP-4` → `SP-5`（🔴 **この順序は固定**・[`user-story-map.md`](./user-story-map.md) §5.5）
- **通過判定**（すべて満たすこと）
  - [ ] `SP-1`〜`SP-5` の各操作レビュー手順を、PR のプレビュー URL 上で完走できる（`SD-1`）
  - [ ] コマンド 1 つで全テストが通り、CI が緑（`AC-10` の基盤部分）
  - [ ] 同じ検索を 2 回実行して 2 回目が外部リクエストを発生させない（`NFR-5` / `NFR-17` / `NFR-18`）
  - [ ] 🔴 **Workers Free の実測（p95 CPU 時間・gzip 後の Worker バンドルサイズ）が済み、Free 継続か Paid 切替かが確定している**（`D-17` / [Cloudflare インフラ設計](../03_design/infrastructure/cloudflare-infrastructure.md) §5.3）
  - [ ] URL のパラメータ名・ロケールの置き場所・キャッシュキー命名・配色の実値が **確定し、ADR（`prd.md` §12 の該当主題）または `prd.md` §13 の未決事項クローズとして記録されている**（🔴 コード内に決めた形跡があるだけでは通過しない。別セッションが別の選択を採れてしまう）
- **ここで初めて可能になること**: 以降のスプリントが **回帰を検知できる状態の上に積める**（`D-9` / トレードオフ `S-2`「基盤 > 機能数」）
- **出口で閉じる未決事項**: `TR-5`（shadcn/ui × Next.js 16 の互換性・`SP-1`）/ `NFR-13` の配色実値（`SP-2`）/ ~~`R-11`（テスト手法）~~ → ✅ **2026-08-18 にクローズ済み**（[テスト戦略](../04_development/testing-strategy.md)）/ `R-7`（`use cache` の実挙動・`SP-5`）/ ~~`D-11`（プレビュー環境のデプロイ先）~~ → ✅ **2026-08-18 に `D-16` で確定済み**（Cloudflare Workers）/ 🔴 **新規: Workers Free の上限（p95 CPU 10 ms・Worker バンドル 3 MB gzip）に収まるかの実測**（`SP-1`・`D-17`）

> 🔴 **`M-1` の目的は動くデモではない。** 「後から変えると全体を書き換える境界」を先に固定することが目的である（`D-9`）。境界が未確定のまま `M-2` へ進まない。

### M-2: MVP 達成（スライス `S-1`）— 🔴 **MVP の線はここ**

- **ゴール**: 与件の受け入れ基準 **11 項目すべて**（`AC-1`〜`AC-11`）を満たし、第三者に引き渡せる状態にする
- **束ねるスプリント**: `SP-6` / `SP-7` / `SP-10`（相互に入れ替え可）→ `SP-8` → `SP-9` → `SP-11`（最後）
  - 🔴 **固定される依存は 2 つだけ**: `SP-8` は `SP-9` より前 / `SP-11` は最後（[`user-story-map.md`](./user-story-map.md) §5.5）
  - ⚠️ **`SP-10`（アクセシビリティ）を最後に回さない**（後から直すと全画面のマークアップに波及する）
- **通過判定**（すべて満たすこと）
  - [ ] [`minimum-requirements.md`](./minimum-requirements.md) §7 のチェックリスト 11 項目を **上から順に実機で確認済み**（`SP-11` の操作レビュー）
  - [ ] [`project-mission.md`](../project-mission.md) の品質ゲート（Lighthouse Accessibility 100 / 主要フローのテスト成功 / キーボード完走 / 秘匿情報の非露出）を **1 つも下回っていない**
  - [ ] `prd.md` §12 の ADR 8 件が揃っている（`NFR-32`）
  - [ ] README に `AR-5` の上乗せ理由と AI 利用範囲が書かれている（`NFR-30` / `NFR-31`）
  - [ ] `R-5`（必要レート枠の逆算）を実施済み。🔵 **これは与件ではなくキャッシュ戦略の設計根拠** であり、`M-4` を通すかどうかと独立に必要（`open-questions.md` の `D-3` 従属事項）
- **MVP に含むもの / 含まないもの**: 🔴 **定義の正本は [`prd.md`](./prd.md) §0.3**（① 与件を満たす最小集合 + ② 後付けコストが高い上乗せ = `AR-4` / `AR-5` / `NFR-17`）。本書はその線を **`M-2` の到達点** として時間軸に置くだけで、内訳を再掲しない
- **出口で開く選択肢**: `M-3`（積み上げ）と `M-4`（公開判断）は **どちらを先に始めてもよい**（互いに依存しない）

> 🔴 **`M-2` は「コードが書けたこと」では通過しない。** 11 項目の実機確認と品質ゲートの充足が通過条件である（[`user-story-map.md`](./user-story-map.md) §7 運用ルール 2）。

### M-3: 積み上げ（スライス `S-2`）

- **ゴール**: 期日まで、単独で操作レビューできる増分を順次追加する
- **束ねるスプリント**: `SP-12` 以降（1 スプリント 1〜2 項目）。対象は `US-10` / `US-27` / `US-28` / `US-29` / `E-20` / `E-21`
- **通過判定**: 🔴 **存在しない。** 完了条件を持たないマイルストーンであり、**期日が来た時点の到達点がそのまま成果** になる
- **着手順序の目安**（期日が近いほど上から順に）

  | 順 | 対象 | 入れると何が良くなるか / 落とすと何を失うか |
  |---|---|---|
  | 1 | `E-21`（翻訳の品質仕上げ・`AR-4`） | i18n 基盤は `M-1` で入っており、動く英語 UI も `SP-8` までに揃っている。**仕上げないと英語 UI の文言が粗いまま残る** |
  | 2 | `US-27`（degraded 表示・`NFR-7`） | レート残量が少ないときの挙動が利用者に伝わる。落とすと「なぜか遅い / 出ない」が説明されない |
  | 3 | `US-10`（topics 絞り込み・`AR-6`） | Phase 2 の差別化（`GR-4`）の土台。**単体では GitHub 純正の `topic:` で代替される**（`Q-4`） |
  | 4 | `US-28` / `US-29`（お気に入り・検索履歴・`AR-7` / `AR-8`） | 再訪時の手間が減る。落としても与件は割れない（端末間で同期しない制約も残る） |
  | 5 | `E-20`（バンドルサイズの CI 可視化・`NFR-28`） | Lighthouse の揺れに左右されない補助指標。ゲート化はしない |

  ⚠️ この順序は **拘束ではない**（相互に依存しないため入れ替えてよい）。期日が確定したら §5 の手順で確定させる。

### M-4: 公開判断ゲート（実装マイルストーンではない）

- **性質**: 🔵 **第三者に使わせる場合にのみ通す。** 選考課題 / ポートフォリオとして提出するだけなら通過不要（`D-3` の主目的は `M-2` で達成される）
- 🔵 **2026-08-18 の変更（`D-16`）**: 事業者選定（`D-7`）は Cloudflare に確定したため **`M-4` から外れた**。本ゲートは「**第三者へ公開するか否か**」の判断に純化する
- **いつ判断するか**: 🔴 **フェーズ番号ではなく「第三者へ公開するかどうか」で判断する**（`R-8`）
- **通過判定**（公開するなら、すべて満たすこと）
  - [ ] `R-8`: GitHub 利用規約 / AUP / API Terms の該当節を一次確認済み（アバター画像の再配信可否を含む）
  - [ ] キャッシュ TTL の具体値が、`M-2` で実施した `R-5` の逆算に基づいて **確定** している（`M-1` の暫定値からの更新）
  - [ ] `R-6`: 運用コストが無料枠に収まることを試算済み（`inception-deck.md` Q10）
  - [ ] **独自ドメインの要否を決定済み**（MVP は `*.workers.dev`。Cloudflare 公式は workers.dev を business-critical 用途には非推奨としている）
  - [ ] **コスト撤退ラインの実額が確定している**（Workers Paid へ移行している場合。Budget alerts は通知のみで停止しないため、Billable Usage API の監視閾値として使う・`A-6`）
  - [ ] **OAuth 検証用の `[env.dev]`（別 Worker）を持つかを決定済み**（`D-21`。プレビューは PR ごとに URL が変わりコールバック URL を事前登録できないため、OAuth 経路は固定 URL の環境でしか事前検証できない）
  - [ ] **gradual deployment（`wrangler versions deploy --percentage`）を導入するかを決定済み**（`D-21`。`INF-21` はロールバックであって段階的展開ではないため、導入には新規決定が要る）
- **通過しない場合の扱い**: 公開しない。🔴 **プロダクトの完成度とは無関係**（未通過は欠陥ではない）

> 🔵 **`M-4` を `M-3` の後に置かない。** 公開判断は積み上げの進捗と独立しており、`M-2` 到達後いつでも通せる。

## 6. スコープ調整の規則（削る順序）

期日が想定より早い / 進捗が想定より遅いと判明したときは、**次の順序でのみ** 削る。

```
① M-3 の下位項目から削る（§3 の着手順序の下から）
        ↓ それでも足りない場合
② M-3 を丸ごと落とす（M-2 到達で与件は満たされている）
        ↓ それでも足りない場合
③ 🔴 ここで止まる。M-1 / M-2 は削らない
```

🔴 **`M-1` / `M-2` を削らない理由**: `M-2` は与件（必達の下限・`D-2`）であり、`M-1` はその到達に必要な境界確定である。`M-1` を削ると `M-2` が「後から全体を書き換える作業」に化けるため、短縮どころか遅くなる（`D-9`）。

⚠️ **`M-1` / `M-2` の内部で削れるものはない、という意味ではない。** `prd.md` §0.3 のとおり、`P1-MVP` のうち **②（後付けコストが高い上乗せ）で、削っても①（与件充足）を割らないもの** は理屈のうえでは削減候補になる。ただし ② は「後から入れると既存コードを書き換える」という理由で MVP に置かれているため、**削ると `M-3` 以降の速度が落ちる**。削る場合は理由を決定ログ（`open-questions.md`）に残す。

## 7. 本書の更新ルール

1. **要件が変わったとき**: 先に [`prd.md`](./prd.md) を更新し、次に [`user-story-map.md`](./user-story-map.md)、最後に本書の参照を合わせる。🔴 **逆順にしない**

4. **新しいマイルストーンを足すとき**: 末尾に `M-6` 以降を振る（既存 ID を詰めない）。⚠️ ただし **判断ゲートを増やす前に、既存マイルストーンの通過判定で表現できないかを先に検討する**（ゲートが増えるほど前に進まなくなる）
5. **期日が確定したとき**: §5 の手順に従う
