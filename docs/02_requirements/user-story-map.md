## 1. バックボーン（ユーザーの行動の流れ）

```
 A-1          A-2           A-3            A-4          A-5           A-6            A-7
┌──────┐   ┌────────┐   ┌──────────┐   ┌────────┐   ┌────────┐   ┌──────────┐   ┌──────────┐
│到達  │→→ │条件を  │→→ │結果を    │→→ │候補を  │→→ │一覧へ  │→→ │つまずき  │   │見つけた  │
│する  │   │組み立て│   │見渡す    │   │見極める│   │戻って  │   │から復帰  │   │ものを    │
│      │   │る      │   │絞り込む  │   │        │   │比べる  │   │する      │   │残す      │
└──────┘   └────────┘   └──────────┘   └────────┘   └────────┘   └──────────┘   └──────────┘
                                                                    ↑ 全工程で         ↑ P1-積み上げ
                                                                      起こりうる
```

| ID | アクティビティ | ユーザーの目的 |
|---|---|---|
| **A-1** | 到達する | アプリを開き、自分の言語で使える状態にする |
| **A-2** | 条件を組み立てる | 探したいものをキーワードと並び順で表現する |
| **A-3** | 結果を見渡す・絞り込む | 一覧をざっと見て、詳細を開く価値のある候補を選別する |
| **A-4** | 候補を見極める | 1 件の詳細を見て、採用可否を判断する |
| **A-5** | 一覧へ戻って比べる | 元の検索条件のまま次の候補へ移る |
| **A-6** | つまずきから復帰する | 何も出ない・失敗したときに、原因を理解して次の手を打つ |
| **A-7** | 見つけたものを残す | 後で見返せるようにする |

> **A-6 は他と性質が違う。** 時系列上の 1 ステップではなく、A-1〜A-5 のどこでも発生しうる。ただし「復帰する」という独立したユーザー体験があるため、バックボーン上に置いて可視化する。

## 6. 本書の使い方（運用ルール）

1. **実装着手時**: ストーリーを GitHub Issue 化する。Issue には **`US-n` と参照要件 ID を書き、受け入れ条件は `AC-n` を参照する**（本文へコピーしない）
2. **スコープ調整時**: 削るのは S-2 から。🔴 **S-0 / S-1 は削らない**（`prd.md` §0.3）
3. **要件が変わったとき**: 先に `prd.md` を更新し、次に本書の参照を合わせる。**逆順にしない**（正本が後追いになると ID の意味が壊れる）
4. **新しいストーリーを足すとき**: 既存 ID を詰めず、末尾に新しい番号を振る
5. **期日が確定したとき**: 本書のスライスを日付へ射影し、**ロードマップを別途起こす**（本書は時間軸を持たない）
