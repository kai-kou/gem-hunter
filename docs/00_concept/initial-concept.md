# プロダクトリサーチレポート：Hidden Gems発掘プラットフォーム "IndieGems"

> 本ドキュメントは本プロジェクトの初期コンセプトです。以降の要件定義・リサーチ・設計・実装の起点として参照してください。

## 1. エグゼクティブサマリー

GitHubには世界中のコードが集約されている一方、検索体験は「既に有名になったリポジトリ」が優遇されるアルゴリズム（SEOやスター数によるマタイ効果）に支配されている。本プロジェクト「IndieGems」は、この情報の非対称性を解消し、個人開発者（インディーハッカー）が自身のプロダクト開発において「真に役立つ、過小評価された名作ライブラリ（Hidden Gems）」を効率的に発見できる検索エンジン・プラットフォームである。

## 2. 市場環境とホワイトスペース分析

### 2.1. 既存ツールとの比較マップ

| カテゴリ | 代表的ツール | 強み | 弱み（ユーザーのペイン） |
|---|---|---|---|
| 公式検索 | GitHub Search | 網羅性・構文検索 | 有名リポジトリが検索上位を占拠し、ノイズが多い |
| コード検索 | grep.app | コード断片の検索 | リポジトリ全体の健全性やトレンドが見えない |
| 統計分析 | OSS Insight | マクロなトレンド可視化 | 個別のニッチな要件に合致するリポジトリ発見には不向き |
| IndieGems（提案） | - | Hidden Gemsの発掘・評価 | - |

### 2.2. 特定されたホワイトスペース

既存ツールは「コードを探す（検索）」か「トレンドを見る（統計）」に終始している。ユーザーが本当に必要としているのは、**「自分の開発課題を解決してくれる、信頼性が高く、かつ有名すぎない良質なライブラリを見つける（ディスカバリー）」**という体験である。

## 3. プロダクト戦略：IndieGems

### 3.1. ターゲットユーザー

- **ペルソナ**: 個人開発者、インディーハッカー、フリーランスエンジニア。
- **インサイト**: 「車輪の再発明はしたくないが、巨大なフレームワークは学習コストが高すぎる。自分のプロダクトにちょうどいい、ミニマルで活発にメンテナンスされているライブラリが欲しい」というニーズを持つ。

### 3.2. コア機能

- **マイクロ・スイートスポット検索**: スター数10〜500のリポジトリに限定し、ノイズ（チュートリアル、課題提出用等）を排除。
- **Gem Score**: 独自のアルゴリズムによる健全性評価（更新頻度、ドキュメント充実度、Issue解決率）。
- **目的別タグ付け**: 技術名ではなく「何を作るか（例: #決済 #CLI軽量化）」での検索。
- **セレンディピティ・レコメンド**: 週刊ダイジェストを通じた、予期せぬ良質リポジトリとの出会い。

### 3.3. 技術的アプローチ

- **データ取得**: GitHub GraphQL APIを活用し、リポジトリのメタデータを効率的に収集。
- **スコアリング**:
  - Maintenance Score = (コミット密度 + Issueクローズ率)
  - Doc Quality Score = (README構造解析)
  - Dependency Signal = (著名プロダクトからの依存数)

## 4. ビジネスモデルとGo-To-Market

### 4.1. マネタイズ（B2Cモデル）

- **Freemium**: 基本的な検索と閲覧は無料。
- **Proサブスクリプション（$5-9/月）**:
  - カスタムアラート（条件合致時のDiscord/Slack通知）。
  - 詳細なリポジトリ分析レポートの閲覧。
  - お気に入り機能とプライベートリスト管理。

### 4.2. 初期GTM戦略

- **Build in Public**: 開発プロセス自体をX (Twitter)やコミュニティで発信。
- **Product Hunt**: 「Stop reinventing the wheel」をテーマにした世界規模でのローンチ。
- **コンテンツマーケティング**: 自動スクレイピングによる「今週の隠れ名作OSS 10選」を継続配信。

## 5. ロードマップ

- **フェーズ1（MVP）**: データ収集パイプライン構築と、検索サイトのミニマル公開。
- **フェーズ2（コミュニティ）**: ユーザーフィードバック機能と、SNSでの拡散用ウィジェット提供。
- **フェーズ3（収益化）**: Pro機能の実装と、パーソナライズされたレコメンデーション精度の向上。
