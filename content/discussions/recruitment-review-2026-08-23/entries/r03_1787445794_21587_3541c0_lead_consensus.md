### 合意した点

1. **与件の受け入れ基準 11 項目・FR-1〜FR-7・状態表示 5 種は全件充足している。** 3 名がそれぞれ独立に実コード・実テストを読んで確認し、自己申告チェックリスト（`minimum-requirements-checklist.md`）との食い違いは見つからなかった。lead も `npm test`（**79 files / 908 tests passed**）・`npx tsc --noEmit`（PASS）・`npx eslint`（エラー 0・警告 3）を自ら実行して再現している。
2. **Watcher 数に `subscribers_count` を採用した判断は減点ではなく加点材料。** GitHub API の `watchers_count` が `stargazers_count` のミラーである既知の癖を踏まえ、要件を字面でなく仕様として解釈している。senior_prod は round 1 の留保を明示的に撤回した。
3. **`next/image` を使わない画像最適化も減点対象から外す。** GitHub 側のサイズパラメータ + 明示 `width`/`height` + `loading="lazy"` は、Cloudflare Workers 実行環境の制約下では等価な代替であると senior_prod が判断を改めた。
4. **同一の欠陥（CI 不在 + Prettier 未接続）を複数軸で重複減点しない。** 3 名とも round 1 では C・D・B に分散計上していた。**C 軸へ集約** する（senior_arch・senior_prod の一本化提案を採用。senior_req の「D 軸で保守性ゲートを見るべき」という立場は少数意見として `dissent` に残す）。
5. **スコープ拡張（Gem Index・OAuth・i18n・LP・AI ハーネス）の評価は F 軸に一本化する。** A 軸は「11 項目を満たしているか」の充足判定に純化する。加点面（`AR-5` で与件が対象外とした項目へは実際に広げていない自制）と減点面（採用課題として指示範囲を超える実装量・運用オーバーヘッド）を F 軸内で相殺し、正味 3/5 とする。
6. **「AI が全工程を自律実行した」という申告はスコアから外す。** senior_prod が自らの round 1 主張を限定し、3 名が一致した: 成果物の品質は実物で検証できており、「候補者本人の技術判断をどこまで読み取れるか」は別の問い。得点化せず `concerns` / `conditions`（面接で直接確認）へ移す。申告が誠実で実ログと矛盾しないこと自体は F 軸のプラス材料として残す。
