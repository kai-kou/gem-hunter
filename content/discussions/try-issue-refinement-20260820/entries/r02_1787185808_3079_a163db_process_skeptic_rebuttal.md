## #109（getByTestId 要求）— 全面的に concession

app_quality の実測（`getByTestId` 0 件 / `getByRole` 79 件）は round1 で自分が挙げなかった論点だが、自分の懸念（死蔵する検査）より **一段深刻**だと認める。死蔵は「実装されず放置」だが、#109 は「実装したら既存の a11y 配慮設計を壊す」regression 要求。**やめる（not_planned）ではなく、Issue タイトル・本文を反転（`getByRole` 優先の明文化 + `getByTestId` 濫用検知）してから残す**という app_quality 案に賛成する。process_skeptic としての教訓を追記したい: この Issue はおそらく机上（Testing Library の一般論の誤記憶）で起票され、**起票時点で実コードを確認していなかった**。今回のように「検査を足す」提案には着手前の実コード grep を Done Criteria に義務付けるべきという一般則を open_questions に残すことを推奨する。

## #134（射程 1/11）— 自分の懸念を補強する実例として reinforce

これは反論ではなく **自分の主張の裏付け**として受け取る。`check_ui_dimensions.py` の `CALL_SITE_REQUIREMENTS` が `search-form.tsx` 1 件だけを登録して以降拡張されていないという事実は、まさに round1 で警告した「検査スクリプトが実装後に放置され死蔵する」パターンが **既にこのリポジトリで実際に起きている**証拠。したがって #134 は「やめる」ではなく残すが、Done Criteria に「拡張する」という曖昧な表現ではなく **`src/ui/` 配下 className 使用 11 ファイル全件を対象に含める**と行数まで明記すべきと修正提案する。そうしないと #134 実装後も次の 1 ファイルだけ足されて再び射程 2/11 で放置される。

## mission_po の high 昇格案（#92 / #125 / #116）

- **#125**: 賛成。コード自身（`container.ts` JSDoc・ADR 0005）が「暫定値」と自己申告しており、検査スクリプト追加ではなく実装債務そのものなので、自分の懸念（死蔵する検査）は当てはまらない。high 継続に異論なし。
- **#92**: 一部反対。app_quality の実地確認で契約テストの大半（`cache.test.ts` `rate-limit.test.ts` `oauth.test.ts`）は既に存在し、残る欠落は「ポート interface の JSDoc に契約を書く」という小工数の文書化のみ。実装インパクトが小さいものを high に置くと、消化スロットで #125 のような本当に重い負債より先に消化される歪みを生む。medium・sp:1〜2 を推奨。
- **#116**: 部分同意・部分反対。「秘匿情報の非露出」という**リスクの重大性**には同意し high 相当と認めるが、round1 で hold とした**実装アプローチ**（再現可能なネットワーク遮断・観測テスト）への懸念は変わらない。フレーキーな E2E ネットワーク監視より、まず「クライアントにバンドルされるコードパスに秘匿 env 変数が渡っていないか」を静的 grep で検査する軽量版にスコープダウンしてから high に上げることを条件付き支持とする。

## backlog_hygiene の merge 支持（#130+#139）— フェーズ分割の具体化

app_quality が実地で `updatedAt` が `pushed_at` ではなく `updated_at` から来ている（`mapper.ts:59`）という **実バグ疑いを発見済み**。これを踏まえフェーズを具体化する:
- **フェーズ 1（#130 が担う。#128 を吸収）**: 語彙表 vs 実装命名 + 「値の出どころ」の静的照合（正規表現ベースで実装容易）。ただし **今回発見済みの `updatedAt` 不整合は検査ツールの完成を待たず、この棚卸しとは別に即バグ修正 Issue として先出しすべき**（実バグを「将来の検査で拾う」対象にして放置しない）。
- **フェーズ 2（#139）**: コード例示ブロックのパース＋実装照合。実装難度が高いため sp を分けて後続にする。
2 フェーズを 1 つの Issue 本文に書き、フェーズ 1 未完了のままフェーズ 2 に着手しないことを明記する。
