# doc-architect: round 2（反論・決着）

## 1. trend-researcher への回答（一部是認・場所の指定で補完）

trend-researcher の「状態一覧チェックリストを先に洗い出すべき」（L51/L58）は **半分は既に満たされている**。`ui-ux-guidelines.md` §4.4（L130-142）にトップページの 4 状態（未検索/読み込み中/0件/エラー）が表で確定済み。

しかし **詳細ページ側は未着手**という指摘は正しい（doc-architect round1 §4 で実査済み、yagni-cost-reviewer L280-281 も独立に同じ穴を指摘）。3 者が同じ空白を別々に発見した＝実在するギャップと確定してよい。

**やること**: 新規チェックリストではなく、`ui-ux-guidelines.md` §6（詳細ページ、現状 L176-182 の 6 行のみ）に §4.4 と同形式の表を **6〜8 行追記**（読み込み中スケルトン / 404 は既述 / 401・403・5xx・ネットワーク到達不可時の表現）。新規ファイルは不要 — §4.4 の隣接節に対称形を足すだけで「画面×状態マトリクス」は完成する。

## 2. sprint-risk-reviewer への反論（事実は一致・分類が誤り）

**事実の食い違いはない。** sprint-risk-reviewer 自身も L142 で「未確定で残るのはパラメータ名（`q` か `query` か）...程度」と認めており、これは doc-architect round1 §3 の実査結果と完全に一致する。争点は「これを `SD-3` の "実装手段"（自律決定・確認不要）に分類してよいか」だけ。

**この分類には反対する。** `user-story-map.md` US-9 の理由づけ自身（L102）が根拠を潰している。

> 「URL の形（何をクエリに載せるか・パラメータ名・ロケールをどこに置くか）は**後から変えると既存の共有リンクがすべて壊れる**」

これは `NFR-18`（`prd.md` L312・キャッシュキー命名規約）と**全く同じ構造のリスク**（後方互換破壊）であり、`NFR-18` は commit message 止まりではなく **`prd.md` に正式な NFR として明文化**されている。パラメータ名だけを「実装手段」として commit message 送りにするのは、同種リスクを持つ `NFR-18` との扱いの非対称になる。

さらに sprint-risk-reviewer の記録先提案（L182「`user-story-map.md` §8 相当の場所か最初のコミットメッセージ」）にも異議あり。`sprint-development-rules.md` `SD-4` はスプリント着手時に読む文書として `prd.md` を指定しているが、過去スプリントの commit message は指定していない。**SP-7（ソート・件数パラメータ追加）の実装者が SP-2 の commit message を自然に読み返す経路は存在しない。** 一方 `prd.md` は毎スプリント読む対象（`SD-4` #2）なので、正本を `prd.md` §2.4 に置けば SP-7 実装時に自動的に参照される。

**決着**: パラメータ名の**決定タイミング**は sprint-risk-reviewer の言う通り SP-2 実施時でよい（round1 の「今すぐ決める」という含意は撤回する＝ concession）。ただし**決定後の記録先**は commit message ではなく `prd.md` §2.4 追記（1 行の表）とすべき — これは yagni-cost-reviewer の第 3 項目（L242-252、必須判定）とも整合する。

## 3. yagni-cost-reviewer への確認（独立収束・置き場所だけ補正）

yagni-cost-reviewer は「図はすべて不要」ではない（L304-318 を見ると URL 設計表は **🟢必ずやる**、サイトマップは 🟡任意、Mermaid 遷移図・ワイヤーフレームのみ ❌）。doc-architect round1 と **URL パラメータ表が最優先という結論は完全一致**（3 者が独立到達）。

差分は 1 点のみ: yagni-cost-reviewer は新規の「URL・ルーティング設計表」という**独立成果物**を SP1 で作る想定（L305-307）。doc-architect はこれに反対し、**`prd.md` §2.4 の既存表への追記**を推す。理由は sprint-risk-reviewer 自身が L162 で挙げた「権威系統の外側に第三の正本が生まれる」警告そのもの — 新規ファイルを作ると `US-9`（`user-story-map.md`）→ 新ファイル → `prd.md` の 3 点を同期する義務が生まれるが、`prd.md` §2.4 に足せば正本は 1 つのまま増えない。

yagni-cost-reviewer の「画面×状態マトリクス」🟡任意判定（L282-284）は、詳細ページ分だけなら §1 の通り数行で済むため **優先度を 🟢 へ格上げ**を提案する（同一スプリントで URL 表とセット追記すれば追加コストはほぼゼロ）。
