## fact_check（round 2・他 3 名への応答）

### 1. req_gate [major] 「Gem Index の母集団と配信」節が Hidden Gem 節と重複 — 部分同意（concession）

実際の本文を突き合わせた。

- Hidden Gem 節（README.md:115）: 「母集団を 12 レジストリ・約 11 万リポジトリへ拡大した実測を受けて `D-36` で再導入した（汚染フィルタとリポジトリ単位の重複排除を通した後の配信プールは 12 レジストリ・**62,483** リポジトリ・`D-37`）」
- 新設節（README.md:141）: 「汚染を落としてから数える: …同一リポジトリを指す複数パッケージはリポジトリ単位で重複排除する。この 2 段を通した結果が配信プールの **62,483** リポジトリ」

**「母集団拡大 → 汚染フィルタ + dedupe → 62,483」という同一の算出根拠が、ほぼ同じ言葉で 2 箇所に書かれている事実**は認める（req_gate の指摘は该当 1〜2 文について正しい）。

ただし完全な二重記述ではない。新設節にしかない情報が過半を占める:
- 「レジストリ別成層化・既定 15,000 件の固定枠」（母数比例だと npm が枠を占める、という設計理由）
- 「配信はレジストリ別シャードの静的アセット + isolate cold start 並列取得 + singleton promise」（配信方式の設計理由）

これらは Hidden Gem 節には存在しない。Hidden Gem 節は「指標の意味・どこで使われるか・何が未確定か」という **利用者向けの説明**、新設節は「母集団をどう作るか・どう配信するか」という **エンジニアリング判断の記録**（`NFR-30` が求める工夫点）であり、役割自体は分かれている。

**fact_check としての結論**: 「二重記述」という指摘は該当 1 文（62,483 の算出根拠を繰り返す部分）に限って事実。req_gate が要求する「レジストリ別成層化・シャード配信を ADR 参照 1 行へ格下げ」までは事実確認の範囲外（要件充足の判断は req_gate 領分）だが、**その 1 文を Hidden Gem 節側の参照リンクに置き換えても新設節の主張（成層化・固定枠・配信方式）は失われない**ことは事実として確認できる。

### 2. req_gate [major] ADR 0014 の設計判断を本文へ昇格 — 同意（concession）

ADR 0014（`docs/adr/0014-zero-query-daily-digest.md`）を確認した。決定の骨子は:
- 発見面をトップページに置き **キーワード非依存**（`A-8`）
- 提示形式は **有限件数（既定 5 件）の日次ダイジェスト。無限フィード・無限スクロールは採らない**
- **日付を唯一のシードとする決定論的生成**。サーバーに個人化状態を持たない。`?date=` で外部から上書きでき、URL 共有だけで再現できる

これに対し README の現行記述を突き合わせると:
- 冒頭（README.md:5）は「日次で入れ替わるダイジェスト『今日の Gem』」とだけ書き、**「なぜ有限 5 件か」「なぜ無限フィード/通知を採らなかったか」「なぜ日付シードで状態を持たないのか」への言及がない**
- Hidden Gem 節（README.md:115）は「① 日次ダイジェストの並び順」を Gem Index の適用先の 1 つとして挙げるのみで、ダイジェスト自体の設計判断（有限件数・決定論的生成）には触れていない

**fact_check としての結論**: 「今日の Gem」の設計判断（ADR 0014 の本体）は README 本文のどこにも実質的に書かれていない、という req_gate の前提は事実。既存記述による代替充足はなく、昇格要求は事実面から支持できる。

### 4. reader_flow の画像トリミング案（digest から装飾イラスト・末尾出典をカット）— D-29 抵触なし、ただし alt 修正が必須（rebuttal + 注意喚起）

`D-29`（`open-questions.md:340`）を確認した。要求しているのは「配信 JSON のトップレベルに `source`/`license` 等のメタデータを含めること」と「**UI にも出典表示を出す運用**」——これは **本番アプリの実行時 UI** に対する要件であり、README のスクリーンショットという静的ドキュメント資産に出典を写り込ませることを義務付けるものではない。

- README 本文には Hidden Gem 節（README.md:120）に既に「被依存数は Ecosyste.ms のオープンデータに委ねる」という帰属の言及があり、画像をトリミングしても **本文からは Ecosyste.ms への言及が消えない**。
- 本番アプリの実際の出典表示（画面下部の注記）自体はコードで実装されているものであり、README のスクリーンショットをどう切り取るかとは無関係に存続する。

**結論**: reader_flow の提案（`mobile-digest.webp` の末尾出典部分 y≈1968〜2392 をカット）は D-29 / CC BY-SA 4.0 のいずれにも抵触しない。

**ただし 1 点、事実整合上の見落としを指摘する**: 現在の alt テキスト（README.md:20）は「末尾に Ecosyste.ms を出典とする注記がある」と明記している。この案どおり画像をトリミングすると **alt テキストが実際の画像内容と食い違う**（存在しない要素の説明が残る）ことになる。トリミングを採用するなら、同じ diff で alt テキストからも当該記述を削るか、「出典注記は画面下部（本 README では非表示）」等に修正する必要がある——これは D-29 とは別の、単純な事実整合の問題として round 3 までに解消すべき。
