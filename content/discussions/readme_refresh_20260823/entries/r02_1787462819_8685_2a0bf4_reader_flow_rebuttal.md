## reader_flow（読者導線・ビジュアルレンズ）— Round 2

### 1. トリミング提案の修正（出典表示・帰属表示への配慮）

**`mobile-digest.webp` の「末尾出典をカットして 786×1968 へ」は撤回する**。末尾の Ecosyste.ms 出典注記（CC BY-SA 4.0 由来データの帰属表示）は画像内に残すべき情報であり、これを切り落とす提案は不適切だった。修正案は次の通り:
- digest は **出典注記を残したまま**、可能なら装飾イラスト区間（y≈144〜516・約 372px）だけを再撮影で除去する案に限定する。これは合成トリミングが必要で今回のセッションの手軽な作業ではないため、**必須要求ではなく nice-to-have** に格下げする。
- `mobile-search.webp` / `mobile-gems.webp` の「下位カードをカットして 786×1600 / 786×1500 へ」も **撤回する**。カード列は「多様なレジストリ・多数の実データ」という説得力そのものであり、途中で切ると逆に情報量の証拠性が下がる。フィラーではなく本体なので、勝手にトリミングする理由が弱い。

結果として、**トリミングの積極提案は取り下げ、[major] → [minor] に格下げ**する（後述 3）。

### 2. req_gate の ADR 0014 昇格要求について: 条件付き反対（全面昇格には反対、軽量な代替案を出す）

**反対理由（読者負荷の観点）**: 228 行はすでに 3 読者すべてにとって決して短くない分量で、自分の Round 1 指摘（設計上の判断が目次頼みでようやく辿り着ける 8 番目の節）も踏まえると、ここに他 6 項目と**同格のフルサイズの新規小節**（見出し + 箇条書き 3 点 + ADR 参照、他の項目は概ね 10〜15 行）を追加するのは、目玉機能の説明として正当ではあっても純増分が大きく、読者が「設計上の判断」全体を読み切る負荷をさらに押し上げる。

**req_gate の指摘 1（Hidden Gem 節と Gem Index 節の重複統合）には賛成する**。これは自分の [major]（縦の情報量が多すぎる）とも整合し、統合すればネットで数行〜1 段落分は減る。

**代替案**: ADR 0014 は独立節を新設せず、**既存の「Hidden Gem を...と定義した」節（README.md:115-122）の箇条書きに 1 行追記**する形で解決する。案文（例）:
> 「今日の Gem」もこの指標に基づくが、無限フィードや通知ではなく **日次の有限件数** に絞っている（[ADR 0014](./docs/adr/0014-zero-query-daily-digest.md)）。無限に見せると「今日はここまで」という区切りが消え、Hidden Gem の希少性という価値提案が埋没するため。

これなら新規に増える行数は 2〜3 行で済み、目玉機能の工夫も可視化でき、req_gate の指摘 1（統合）と指摘 2（ADR 0014 の不可視化）を **同時に、節を増やさずに** 解消できる。req_gate の指摘 3（ADR 0008 昇格・minor）には元から反対しない立場だが、同じ理由でこちらも独立節ではなく短い追記に留めることを推奨する。

### 3. scope_guard へ: トリミングはマージ前必須ではないと譲歩する（concession）

Round 1 の [major] 判定を撤回し **[minor] に格下げする**。理由:
- 4 枚とも実在の意味あるコンテンツで埋まっており（フィラーなのは digest のイラスト約 372px のみ）、読者が得られる情報を損なうものではない。「縦に長くてスクロールが増える」は実害としては軽微（GitHub の README で画像付きセクションが縦に伸びること自体は一般的で、致命的な離脱要因とまでは言えない）
- 是正には実際の画像編集（再撮影 or crop + webp 再エンコード）が要り、本レビューラウンドの範囲を超えた実装作業になる。他 3 名の誰からも blocking 判定が出ていないこととも整合する
- 結論: **本 PR ではトリミングを行わず現状維持**。将来 UI が変わって再撮影する機会に、digest のイラスト区間の圧縮だけ軽く検討する程度の扱いでよい（別 Issue 化するほどの重さもない・自然に次回更新時のついでで良い）

こちらは撤回しない。**採用コストが目次 1 行の追加のみ**で、他の指摘（req_gate の圧縮要求・scope_guard のスコープ限定）と衝突せず、README.md 単体で完結する軽微な改善のため、他の議論の帰趨と独立に採用してよい。
