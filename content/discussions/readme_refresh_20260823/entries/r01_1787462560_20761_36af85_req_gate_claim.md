### 指摘

1. **[major]** README「設計上の判断」節（README.md:142-148「Gem Index の母集団と配信の作り方」）と、直前の「Hidden Gem を...と定義した」節（README.md:115-122）が、母集団拡大の同一事実（約 11 万リポジトリ → 汚染フィルタ + repo 単位 dedupe 後 62,483）をほぼ同じ言葉で二重に説明している。1 箇所（Hidden Gem 節）に統合し、レジストリ別成層化・シャード配信という実装寄りの内容は ADR 0009 §2.3 か新設 ADR への参照 1 行に格下げすることを要求する。二重記述はどちらか一方だけが将来更新され食い違う desync リスクを生む。
2. **[major]** ADR 0014（キーワード非依存の発見面＝「今日の Gem」を日次の有限ダイジェストとして実装する判断）が「設計上の判断」節に一切現れない。「今日の Gem」は README 冒頭（README.md:5）で最初に紹介される目玉機能であり、`AR-9`/`AR-10`/`AC-9` に対応する PRD §12 記録済み ADR でもあるのに、ADR 索引表（README.md:214）に埋もれたままで「なぜ有限件数か・なぜ無限フィードや通知を採らなかったか」という工夫が本文で語られていない。他 6 項目（i18n 自前実装・a11y ゲート限定・next/image 不使用等）と同格の 1 節として昇格を要求する。
3. **[minor]** ADR 0008（`FR-7` でページネーションを選び無限スクロールを採らない判断）は与件 §3 が明示的に二者択一を課した MVP 必須要件であり、`AC-7` 対応の ADR でもあるが、本文には現れず ADR 索引のみ。i18n・エラー分類と同格の「こだわり」候補であり、余裕があれば 1 段落の昇格を提案する（必須ではない）。
4. **[minor]** 「Gem Index の母集団と配信の作り方」節（README.md:148「レジストリごとに分割した静的 JSON を isolate の cold start で並列取得...」）はエラー分類節（README.md:136 `src/domain/errors.ts` へのリンクあり）と異なり、実装ファイルへのリンクが無く「書いてあるが第三者に追えない」。`src/infrastructure/platform/static-gem-index.ts`（存在確認済み）等への参照を足すべき。指摘 1 で節を圧縮する際にあわせて解消できる。
