## req_gate（与件・要件充足レンズ）— round 2

### reader_flow のトリミング提案への回答（与件 §6 の観点）

`mobile-digest.webp` の出典注記（Ecosyste.ms・末尾約 424px）と、`mobile-search.webp`/`mobile-gems.webp` の後半カード群をカットする提案について、**与件 §6（セットアップ手順 / 設計上の判断 / AI 利用範囲）そのものへの抵触はない**。これらの要件は README の「本文」に対する記載義務であり、画像内にどこまで写っているかを規定していない。トリミングで NFR-29〜32 / AC-11 のいずれも損なわれない。

ただし **1 点、私のレンズから見て見落とせない副作用がある**: `mobile-digest.webp` の alt テキスト（README.md:20）は「末尾に Ecosyste.ms を出典とする注記がある」と明記しており、`mobile-search.webp` の alt（README.md:20）も「symfony/yaml, eemeli/yaml, nodeca/js-yaml」を含む後半カードの内容を含んでいる可能性がある（reader_flow の実見結果によれば search 画像は 6 件のカードを alt が説明）。**トリミングを採用するなら、alt テキストを実際に見える範囲だけに書き直す必要がある**（見えなくなった要素を alt に残すと「書いてあるが画像を見ても確認できない」= 事実と乖離した代替テキストになる）。これは新たな指摘として追加する。

- **[minor・条件付き]** reader_flow のトリミング案（digest 末尾カット / search・gems 後半カット）を採用する場合、対応する alt テキストからも切り取られた要素の説明を削除すること。トリミングしないなら本指摘は無効。

### scope_guard の「ADR 0012 行は残す」への回答（NFR-30/31 の観点）

**同意する。** ADR 索引表（README.md:199-215）の 0012 行は「設計上の判断」本文（採否理由を語る散文）ではなく、`NFR-32`（ADR 記録の完全性）に対応する機械検証対象の目次であり、そこに書かれているのは ADR ファイルの見出しをそのまま転記した中立的な 1 行（「任意の GitHub OAuth ログインを、与件が対象外とした認証に上乗せする」）にすぎない。ユーザー制約（「過去に対応した認証に関する記載は含めない」）が禁じているのは PR #469 で除去済みの **正当化ロジック**（AR-5 節）であり、ADR の存在自体を隠すことまでは要求していない ——というのが D-39 の read（scope_guard 提示）でもあり、私のレンズでも一致する。

むしろ **私のレンズからは追加の理由がある**: `NFR-32` は「技術的意思決定を ADR として記録する」ことを求め、PRD §12 の記録済み ADR 一覧（0012 含む）と README の索引を一致させる要求（`check_adr_coverage.py`）がある。0012 行を消すと、與件 §6 が求める「重要な技術的意思決定の記録」自体が README 上で **不完全になる**（NFR-32 違反）。scope_guard の「機械ゲートを壊す」という技術的理由に、「NFR-32 の充足を壊す」という要件面の理由を重ねて支持する。

### fact_check の「事実誤り 0 件」との整合性

**矛盾しない。両指摘とも維持する。** fact_check の検証は「今回書かれた個々の記述が実ファイル・実データと一致しているか」という **正確性** の軸であり、私の round 1 指摘 1・2 は「正確だが構成上どう配置されているか」という **要件充足・可読性（与件 §6 の『工夫した点』としての取捨選択）** の軸で、評価対象が異なる。

- **指摘 1（Gem Index 母集団の重複記述）**: fact_check は Hidden Gem 節の「62,483 は D-37 適用後」「D-36 は約 11 万」という数値を ✅ 判定しているが、これは Hidden Gem 節・Gem Index 母集団節の **どちらの記述も現時点では正確** であることを示しただけで、「同じ事実を 2 箇所に書く設計が妥当か」には答えていない。むしろ fact_check が両節の数値を個別に裏取りできた事実は、**2 箇所に同じ実測値が実在する**ことの追認であり、私の「重複している」という指摘の前提（2 箇所に同内容がある）を補強する。将来 D-36/D-37 の値が更新されたとき、2 箇所同時に直さなければ整合が崩れるという desync リスクは、現時点の正確性とは独立した論点として残る。**維持する（major）**。
- **指摘 2（ADR 0014 の昇格要求）**: fact_check の検証項目に ADR 0014（今日の Gem のダイジェスト設計）そのものへの言及はなく、「事実誤りが無い」という結論は「本文に書かれていない」ことの当否を判定していない。ADR 0014 が本文に無いのは「誤り」ではなく「欠落」であり、fact_check のスコープ（記述済み内容の正確性）とは独立した与件充足の論点。**維持する（major）**。
