### ④ ADR 0004 への 1 行追記の妥当性

`git diff origin/main...HEAD -- docs/adr/0004-release-cycle-trunk-based.md` は「代償 | 緩和策」表の 1 セルに **2026-08-23 追記** を 1 文追加するだけ（既存文は変更なし・追記のみ）。内容は「GitHub Actions が起動できないため、このテストゲートは CI ではなくセッションが `main` HEAD で `npm run check` を再実行する形で運用している」。

**判定: スコープ内（README の記述の裏付けとして必要な矛盾解消）**。理由:
- 今回の README 改稿は「リリースサイクル: 常設の dev 環境を持たない（`D-21`）」節の本文を「CI ゲート」→「セッションが実行するゲート」へ書き換えている（`README.md` 該当箇所の diff で確認）。これは ADR 0004 の同じ「代償/緩和策」表の記述（「`main` マージ後のテストゲート」＝ CI 前提の書きぶりのまま）と食い違う状態を放置すると、README と ADR 0004 が同一事象について異なる実装（CI vs セッション実行）を主張したままになる。
- `docs/rules/sprint-development-rules.md` `SD-4` は「ドキュメント間が矛盾していたら権威順で解決し、矛盾自体を修正する（放置しない）」と明記。本追記は権威順（現行コード実態 = セッション実行）に沿った是正であり、README 側の書き換えが原因で新たに露呈した矛盾を同じ PR で埋めるものなので、`core-principles.md` CP-1 の「自分の変更が作ったコードパス上の壊れは即修正する」に相当する（無関係な既存の壊れを持ち込む＝ NG のケースには当たらない）。
- 変更が **1 行の追記のみ**（既存の決定文・却下案は一切書き換えていない）で、影響範囲が README の当該記述と完全に一致する主題に閉じている点も、スコープ逸脱でないことを裏付ける。

以上より、争点 C は「3 項目とも現状維持（残す）」、争点 F の ADR 0004 追記は「スコープ内」、`.github/workflows` 齟齬・チェック本数齟齬は「別 Issue（out_of_scope）」を推奨する。
