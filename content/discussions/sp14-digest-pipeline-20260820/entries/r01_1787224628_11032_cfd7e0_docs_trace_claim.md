### ⚠️ 矛盾 1: ADR 0014 frontmatter と本文の齟齬
**位置**: ADR 0014 冒頭行 5
```
- **対応要件**: `AR-9` / `AR-10` / `US-30`〜`US-33` / `D-27`〜`D-29` / `AC-9`
```

**本文での自己矛盾指摘**: ADR 0014 §2 冒頭（赤字段落）
```
🔴 **frontmatter の `対応要件` にある `AC-9` について**: 本 ADR が追加する機能は上乗せ要件
（`AR-9` / `AR-10`）であり、`user-story-map.md` の `SP-14` / `SP-15` が明記するとおり
**新しい `AC-n` を作らない**（両スプリントとも「対応 `AC`: なし」）。
ただし既存の `AC-9`（キーボードのみで完走できる）は全画面に適用される横断要件であり、
本 ADR が追加する発見面もこれを当然に満たす。frontmatter の `AC-9` はこの横断適用を指しており、
`SP-14` 固有の新規受け入れ条件ではない。
```

**実装状況**:
- user-story-map.md SP-14 line 508: 「対応 `AC`: なし（上乗せ要件 `AR-9`）」✅
- user-story-map.md SP-15 line 522: 「対応 `AC`: なし（上乗せ要件 `AR-9` / `AR-10`）」✅
- user-story-map.md SP-16 line 539: 「対応 `AC`: なし（上乗せ要件 `AR-2` の拡張 + `GR-4`）」✅

**所見**: frontmatter の `AC-9` 記載は冗長。本文で自己矛盾を指摘して正当化しているが、
読者は frontmatter だけを見ると「新規 AC を作る」と誤解する可能性がある。frontmatter から
`AC-9` を削除し、本文の説明に統一すべき。

**prd.md §13** の表（未決事項）の関連行（line 627-630）:
```
| Phase 2 のパラメータ 5 点（母集団定義・しきい値・配信件数・対象エコシステム最終確定・名前解決の例外処理） | 実データのサイズと分布（`SP-14` 着手直後に実測） |
```

**統一提案**: 正本を `prd.md` §13 に一本化し、各 ADR はそこへ参照リンクで指す。あるいは Phase 1 終盤の決定（D-10 など）として open-questions.md に記録する。

### ⚠️ 重複 5: ADR 0009 と ADR 0014 の役割分担は正しいが、パラメータの SSOT が一意でない
**ADR 0009** (定義レイヤ): 「`Gem Index` とは何か」の定義 ✅
**ADR 0014** (実装レイヤ): 「日次ダイジェストをどう実装するか」の設計 ✅

**問題**: 未決パラメータ（しきい値・配信件数等）が両者で言及され、**どちらが承認権者か**が不明。
- ADR 0009 の表に書かれた事項 → ADR 0009 の承認者が決める？
- ADR 0014 の表に書かれた事項 → ADR 0014 の承認者が決める？
- prd.md §13 に書かれた事項 → PO / Product Owner が決める？

**所見**: Phase 2 着手時に「何を誰が決めるのか」の責務分担を明記する必要がある。
