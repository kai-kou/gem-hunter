### 🔴 critical 候補

**C-1. 環境変数表（29-39行目）: `SESSION_ENCRYPTION_KEY` 行の「未設定時の挙動」が実装と食い違う**

- README 39 行目: `SESSION_ENCRYPTION_KEY` | ... | `セッション機能が無効化される`
- 実装（`/home/user/gem-hunter/src/composition/auth.ts:28-35`）:
  ```ts
  /**
   * ログイン導線を表示してよいか。OAuth 3 変数 + セッション暗号鍵の計 4 変数が揃っているかで
   * composition root が一元判定する
   */
  export function isAuthConfigured(): boolean {
    return oauthCredentialsConfigured() && sessionEncryptionConfigured()
  }
  ```
  `isAuthConfigured()` は `app/[locale]/page.tsx` 等でログイン導線の表示ゲートに使われている（grep 確認済み）。
- **何が食い違うか**: README は「OAuth 3 変数が揃わない → ログイン導線が無効化」「`SESSION_ENCRYPTION_KEY` が無い → セッション機能が無効化」と、あたかも 2 つの独立した障害モードのように書いているが、実装では **`SESSION_ENCRYPTION_KEY` 単体の欠落でもログイン導線そのものが非表示になる**（OAuth 3 変数が揃っていても同じ「静かに無効化」が起きる）。README の書き方だと「OAuth 3 変数さえ揃えればログインボタンが出る」と誤読され、`SESSION_ENCRYPTION_KEY` を設定し忘れた開発者が「ボタンが出ない」原因を誤診断しかねない。
- **直し方（1 文）**: `SESSION_ENCRYPTION_KEY` 行を「同上（ログイン導線はこの 4 変数すべてが揃って初めて表示される。本行のみ欠落してもログイン導線ごと静かに無効化される）」に書き換え、`GITHUB_OAUTH_*` 3 行の「未設定時の挙動」も「（`SESSION_ENCRYPTION_KEY` を含む）4 変数が揃わない限り」に修正する。
