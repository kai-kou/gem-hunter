## 2. 議論では決着せず、lead が裁定した点

### V-1. `new-01`（slide 1・表紙）の「見っける」— **誤検出。この理由での再生成は却下する**

`visual_assets` が round 1・2 とも「確信度: 高」で主張し、`project_truth` も追認したが、**lead が該当箇所のみを 8 倍拡大して測った結果、全角の `つ` であることが確定した**。

判別に使うべきは字の高さではなく **横幅** である。`つ` はもともと平たい字形なので全角でも高さは低く、高さで判定すると小書きに見える。一方 **小書きの `っ` は約 60% に縮小されるので周囲の字より横幅が狭くなる**。実測（8 倍拡大時のピクセル）は `つ` 約 290 / `け` 約 190 / `る` 約 230 で、**`つ` が 3 字中もっとも広い**。小書きならもっとも狭くなるはずなので全角の `つ` である。

→ **一字一句違反は存在しない。**「誤字修正のため再生成は不可避」という前提に立っていた `narrative_design` の round 2 concession は、前提ごと無効になる。

### V-2. それでも `new-01` は再生成する（別の理由で）

表紙の焼き込みテキストに **「開発者向け解説 / 2026-08-23」** という日付が入っている。今回 2026-08-24 に改訂する以上、この日付は更新する（前回改訂 2026-08-23 でも、まさに日付更新を理由に `new-01` を再生成した前例がある）。

再生成が発生するので、`narrative_design` が指摘した **本文 1 点目「gem-hunter」が見出しと重複して情報価値ゼロ** という問題も、限界費用ゼロで同時に解消する。

### V-3. slide 6 は `08-doc-relations.webp` の流用をやめ、新規生成へ差し替える（`replace`）

`visual_assets` の (b) は **lead も独自に crop 拡大して事実と確認した**（帯タグ「ADR14件」・中段カード「技術意思決定14件」の 2 か所。実測 15 件）。さらに同じ図の **「ルール57件」「CP-1〜6等57ファイル」も実態とずれる**（`docs/rules/*.md` は 56 件・サブディレクトリ込みで 66 件。どちらでも 57 にならない）。

`visual_assets` が挙げた代替案のうち、① 本文で 15 本と明示して上書き は「同一スライド内で 14 と 15 が同時に見える」矛盾を **可視化・悪化** させるため棄却、② 他の既存資産で代替 は該当なし、③ 画像なしテキスト版 はデッキ全体のビジュアル言語を壊すため棄却 — という整理に lead も同意する。`10-gem-score.webp` を差し替えた前例（画像内の断定的数字が実装事実と食い違う）と同型であり、同じ基準を今回だけ緩める理由がない。

**新画像の ID は `new-10` を使う**（現在の欠番。番号系列の穴が埋まる）。`visual_assets` の前提条件（「ルール57件」の実測が確定するまで数字を焼き込まない）を採用し、**新モチーフには陳腐化する具体数字を焼き込まない**（`ADR n 件` `ルール n 件` の類を入れない）。

🔵 **根本原因はデッキ側ではない**: `tools/infographic/specs/design.json` の `doc-relations.key_numbers` が `["6フェーズ", "ADR14件", "ルール57件", "3正本(設計)"]` とハードコードされたまま ADR 追加に追随していない。同じ問題が `extra1.json` の `adr-map`（`09-adr-map.webp`・`"ADR総数 14件"`）にもある。これは `docs/infographics/` という別レーンの資産の問題なので **本 PR では直さず、フォローアップとして記録する**（スコープ外の改善は別 Issue・CP-1）。

### V-4. `text_budget` は緩和するが、`visual_assets` の提案値は採らない（再較正する）
