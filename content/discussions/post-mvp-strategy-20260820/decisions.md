# MVP 後の開発方針: 確定した決定（Issue #218・2026-08-20 JST）

> 出典: 飼い主の明示指示 + `content/discussions/post-mvp-strategy-20260820/whiteboard.md`（専門チーム 5 名・2 ラウンドの議論）の verdict。
> リサーチの根拠は `content/research/20260820-zero-query-discovery_deep_research.md` と `..._supplement.md`。

## 0. 飼い主の意向（原文に近い形）

> MVP 後の開発について方針を定めたい。**初期コンセプトを実現させたい** が、キーワード入力だけでなく、**キーワード入力せずともリマインド的なリストアップ** ができてもよい。

## 1. 位置づけ — `M-5`（Phase 2 着手判断ゲート）を通過させる

- MVP（`M-2` / スライス `S-1`）は `SP-11`（#212）で達成済み。
- 飼い主の意向により **`M-5`（Phase 2 着手判断ゲート）を「着手する」で通過** させる。
- これに伴い **スライス `S-3` の位置づけを「Phase 2 構想・🔴 実装しない」から「実装対象」へ格上げ** する。`GR-1`〜`GR-7` は構想ではなく実装対象になる。
- 🔴 `D-3`（主目的は選考課題 / ポートフォリオ・収益化は目的としない）は **変更しない**。Phase 2 着手はこの目的と矛盾しない（運用継続を阻害しない設計という制約もそのまま維持する）。

## 2. 飼い主が選択した仕様分岐（`AskUserQuestion` で確認済み）

| # | 分岐 | 選択 |
|---|---|---|
| 1 | 「今日の Gem」の入口 | **トップページ（`/{locale}`）に置く**。開いた瞬間に一覧が見える。検索窓は同じページの上部に残し、MVP の検索動線を壊さない |
| 2 | 更新粒度 | **日次**。日付を唯一のシードとする決定論的生成（同じ日は全員同じ並び・翌日入れ替わる） |
| 3 | `S-2` 積み上げとの順序 | **Gem を先に出し、`S-2`（お気に入り・検索履歴・topics 絞り込み）は後で統合設計する** |

## 3. 専門チームの議論で確定した設計

### 3.1. 次スプリントの切り方 — 薄い垂直スライス（水平分割しない）

- **「npm 1 エコシステムの Gem Index パイプライン + それを描画する日次ダイジェスト画面」を 1 本のスプリント** にする。
- ❌ 「データ基盤だけ」「UI だけ」の水平分割は採らない。理由: 静的 JSON を DevTools で目視確認するのは `user-story-map.md` §5.2 `C-2`（デモ手順 5 行・アプリを操作して確認）を満たさない。加えて実データを見ずに UI の情報設計を決めると作り直しになる。

### 3.2. 「リマインド」の実体

| 案 | 判定 |
|---|---|
| 日次の有限ダイジェスト | 🔵 **採用（核）**。無限フィードは NN/g 基準で比較・検分用途に非推奨、かつキーボード操作を複雑にするため `AC-9` / Lighthouse A11y 100 と衝突する |
| 日付シードによる決定論的生成 | 🔵 **採用（内部実装）**。同じ日は全員同じ並び |
| 時間帯シャッフル（Product Hunt 30 分周期型） | ❌ **独立機能としては不採用**。開いている間に内容が動く実装は WCAG 2.2.2（Pause, Stop, Hide）に抵触するリスク |
| 前回訪問からの差分 | 🔵 **上乗せに格下げ + フォールバック必須**。Safari ITP の 7 日キャップは格下げでは消えない。タイムスタンプ喪失時は全件表示へ自然劣化させる（エラー・空画面を出さない）ことが **必須要件** |
| RSS 配信 | 🔵 **採用可（後続スプリント）**。`GR-7` の延長線上。購読者リストを持たない Pull 型のため `D-5` の撤回は不要 |
| メール / push 通知 | ❌ **不可**。配信先リストの永続化が `D-14`・`D-18` に正面抵触 |
| ログイン限定のパーソナライズ | ❌ **不可**。`D-6`（ログインで機能差を作らない）に抵触 |
| `package.json` 貼り付けによる文脈入力 | ⏸ **今回のスコープ外だが「不採用」ではない**。別 Issue として起票する |

### 3.3. Gem Index — 算出方法は [ADR 0009](../../docs/adr/0009-hidden-gem-score-definition.md) で決定済み

- `Gem Index` = エコシステム内の「被依存数パーセンタイル順位」−「star パーセンタイル順位」。健全性（OpenSSF）は足切りに使い、**2 軸を合算しない**。この場で再議論しない。
- 未確定なのは ADR §2.3 が挙げる 5 点（母集団定義・しきい値・配信件数・対象エコシステム最終確定・名前解決）のみ。
- 🔴 **母集団の取り違えを禁じる**: 「薄いスライス」とは **エコシステムを npm 1 つに限る** という意味であり、npm の中をさらにサンプリングすることではない。パーセンタイルは npm 全量で計算し、絞ってよいのは **表示候補プールの件数だけ**。取り違えると母集団が有名パッケージだけになり残差の分散が消え、`R-2` 違反（GitHub Trending の劣化コピー）が画面上で実証されてしまう。

### 3.4. データ基盤

- Ecosyste.ms の **S3 バルクダンプ**（`https://ecosystems-data.s3.amazonaws.com/packages-[DATE].tar.gz`・約 1,310 万パッケージ・2〜4 ヶ月毎更新）を使う。API での全件走査はしない。
- バッチは **Cloudflare の外**（セッション / Routine の cron）で回し、生成した静的 JSON を git commit → デプロイで **Static Assets** として丸ごと差し替える。
- `D-18`（永続ストアを採用しない）との境界を 1 行で確定する: **「Worker がそのファイルへ実行時に書き込むか？」**。No なら `D-18` の対象外。バッチ生成 → デプロイ差し替えは No 側。この誤読リスクは実在するため **`D-18` に注記を追加する**。
- SPOF（バッチが止まると更新が止まる）は「無害化 + 検知して自己修復」で対処する。配信自体は止まらず劣化するのは鮮度だけ。鮮度チェックを既存の衛生スロットに載せる。
- 健全性フィルタは **OpenSSF Scorecard（`api.scorecard.dev`・週次・100 万件規模・API キー不要）** を第一候補にする。`criticality_score` は最終 push が 2025-12-02 で cron の稼働継続が未確認のため、依存する前に鮮度を実測する。

### 3.5. ライセンスと帰属表示

- Ecosyste.ms のデータは **CC BY-SA 4.0**（公式ドキュメントで逐語確認済み）。コードは AGPL v3。
- 配信 JSON のトップレベルに帰属メタデータ（`source` / `license` / `source_license_url` / 改変の明示）を持たせ、UI にも出典表示を出す。
- 🔴 **Ecosyste.ms の生テキスト（description 等）は再配信せず、数値・識別子・自作の派生値に限定する**。生テキストの転載は "substantial portion" の解釈を保守側へ押す。
- ShareAlike の適用範囲の最終判断は、**第三者へ公開するかを決める時点**（`prd.md` §13 の「GitHub 利用規約の一次確認」と同じタイミング）に合わせる。

## 5. `SP-14` / `SP-15` の内容

### SP-14: キーワードを入力しなくても、その日の Gem が一覧で出る（`sp:8`）

- **含む**: `US-30` / `US-31` / `E-24` / `A-8`（新設）
- **操作レビュー**:
  1. プレビュー URL を開く
  2. 検索せずに「今日の Gem」が有限件数（既定 5 件）表示される
  3. リロードしても同じ順序が再現する
  4. 日付を翌日に進めると顔ぶれが入れ替わる
  5. Tab と Enter だけで一覧から詳細まで完走できる
- **対応 `AC`**: なし（上乗せ要件 `AR-9`）

### SP-15: ダイジェストの鮮度と出典が保証され、再訪時に前回からの差分がわかる（`sp:5`）

- **含む**: `US-32` / `US-33` / `E-25` / `AR-10`
- **操作レビュー**:
  1. ダイジェストに出典表示（Ecosyste.ms / CC BY-SA 4.0）とデータ生成日が出ている
  2. 再訪すると前回以降に入れ替わった項目が識別できる
  3. ブラウザのストレージを消してから開くと「初回として全件表示している」旨が出て壊れない
  4. RSS の URL を購読すると同じ内容が取得できる

## 6. 着手時に潰す前提（`critical`）

1. **母集団の取り違え**（§3.3）。`SP-14` のスキーマ設計時に不変条件として固定する。
2. **S3 ダンプに集計フィールド（`dependent_packages_count` / `rankings`）が含まれるかが未検証**。含まれない場合はパーセンタイルを自前計算するか API 併用になり見積もりが変わる。着手直後に実ファイルで確認する。
3. **`criticality_score` の鮮度が未確認**。健全性フィルタに使う前に実測し、停止していれば Scorecard へ寄せる。
4. **Safari ITP の 7 日キャップは設計で消せない**。フォールバックは任意機能ではなく必須要件。
