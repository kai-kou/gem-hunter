# Post-MVP 戦略検討：「キーワード入力なしの発見体験を Phase 1 に追加」の場合のドキュメント整合性チェック

作成日: 2026-08-20 JST  
分析者: docs_trace  
ラウンド: 1（claim）

---

## 1. D-3 との矛盾分析（現状の線引きを覆す場合）

### 現行決定（D-3）
- `prd.md` §1.5: Phase 2 = "Gem Index による発見機能"。構想のみ、Phase 1 では実装しない
- `inception-deck.md` §Q2: Phase 1 は「キーワード検索 Web アプリ」。差別化部分（残差による並べ替え）は Phase 2

### 新提案がもたらす矛盾
**キーワード入力なしの発見体験を Phase 1 に追加する場合、以下 3 パターンのいずれかで D-3 が矛盾する：**

| パターン | 説明 | 矛盾の発生箇所 |
|---|---|---|
| **A: Gem Index を前倒し** | 被依存数ランキング（残差）を Phase 1 に実装する | `prd.md` §1.5 が「Phase 1 では実装しない」と明記 / `inception-deck.md` Q2 が「Phase 2 まで含めた完成形」と明記 |
| **B: 別の発見方式（トレンド等）** | GitHub API の既存データ（star順、更新順等）を使って発見体験を提供 | `inception-deck.md` §Q4.2 が「Phase 2 以外の発見機能は掲載しない」と記載。新方式が追加されるなら記載が矛盾 |
| **C: topics 活用の前倒し** | 人気 topics の一覧→フィルタで発見を促進（絞り込みの反対向き） | topics は `US-10`（S-2・積み上げスライス）。Phase 1 に移動する場合、スライス割当と優先度が矛盾 |

## 2. バックボーン（A-1〜A-7）の整合性

### 現行バックボーン
```
A-1: 到達する → A-2: 条件を組み立てる → A-3: 結果を見渡す
            → A-4: 候補を見極める → A-5: 比べる → A-6: 復帰 → A-7: 残す
```

### A-2 の現在の定義
**"探したいものを** キーワードと並び順 **で表現する"**（`user-story-map.md` §1）

### 新方式との適合性
**キーワード入力なしの発見（例：「今人気の topics」「最新リポジトリ」「Gem ランキング」）は A-2 に当てはまらない。**

| 方式 | A-2 への適合 | 必要な対応 |
|---|---|---|
| Gem ランキング表示 | 不適合（キーワード不要） | **新 A-n を追加** (例: A-2b「推奨を探す」) または A-2 を改訂（「検索条件 = キーワード + 発見モード」） |
| topics から逆引き | 部分適合（ソート選択肢に topics フィルタを足すだけ） | A-2 に topics 選択肢を明記する修正で対応可 |
| 日次/週次ダイジェスト | 不適合（時系列、キーワード概念なし） | **新 A-n を追加** または A-1 に「初期表示モード選択」を足す |

### 結論
- **パターン A（Gem Index 前倒し）・パターン B（別発見方式）** → 新 A-n 追加またはバックボーン再構成が必須
- **パターン C（topics 前倒し）** → A-2 の記述修正で対応可（バックボーン自体は変わらない）

## 3. Q4.2（やらないこと）リストとの矛盾チェック

### 現行「やらないこと」
| 項目 | 根拠 |
|---|---|
| 通知・アラート・週刊ダイジェストの配信 | Q-5（DB レス原則 `D-5` との衝突） |
| 目的別タグの自前生成（LLM 分類） | Q-4（維持コストが運用継続と両立しない） |
| Phase 2（Gem Index）の実装 | D-3 / D-1 |

### パターン別の「やらないこと」抵触状況

| パターン | 抵触項目 | 回避方法 |
|---|---|---|
| **A: Gem Index 前倒し** | 「Phase 2 の実装」に直撃 | `inception-deck.md` §Q4.2 からこの行を削除・§Q4.4 に移動 |
| **B: 週刊ダイジェスト** | 「週刊ダイジェストの配信」に直撃 | `D-5` の DB レス原則を撤回する新決定 `D-n` が必須 |
| **B: 通知** | 「通知・アラートの配信」に直撃 | 同上 |
| **C: topics 活用** | 直撃なし（topics は既に表示項目に含まれる） | `inception-deck.md` §Q4.2 の修正なし |

### 既存決定との関係（Q-4 / Q-5）
- **Q-4 の従属事項**（`open-questions.md` §4.1）:
  - "topics は追加コストなしで使える。Phase 1 の一覧カード・詳細ページに表示する案は P1-積み上げの有力候補"
  - → topics 表示は既に Phase 1 の検討候補。発見方式として前倒しするのは自然な流れ

- **Q-5 の従属事項**（`open-questions.md` §4.2）:
  - "お気に入り（`localStorage` で実現可）→ P1-積み上げ"
  - "週刊ダイジェスト → P2 かつ条件付き（DB レス原則との衝突）。代替案：静的「今週の Gem 一覧ページ」"
  - → 週刊ダイジェストは既に「原則衝突」として認識済み。今回の追加でこれを前倒しする場合、`D-5` の再判断が不可欠

## 結論（ロンド 2 への参考）

**実装方針が確定していない段階での整合性チェック:**

1. **パターン A（Gem Index 前倒し）**
   - D-3 の「Phase 2 実装しない」を撤回する必要あり
   - ただし Gem Index は **被依存数データ（GitHub API に存在しない）** に依存するため、Phase 1 では不可能（`prd.md` §2.2）
   - 実装可能な形に再定義が必須

2. **パターン B（別発見方式：週刊ダイジェスト / RSS 等）**
   - D-5（DB レス原則）と Q-5（やらないこと）を同時に撤回する必要あり
   - バックボーン改訂で新 A-n を追加（複雑度高）

3. **パターン C（topics 活用の前倒し）**
   - 既存 Q-4 決定（§4.1）「topics は P1-積み上げ候補」と矛盾しない
   - `user-story-map.md` の優先度変更（`US-10` S-2 → S-1）のみで対応可
   - **整合性が最も高い選択肢**
